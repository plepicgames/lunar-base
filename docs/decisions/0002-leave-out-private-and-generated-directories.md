# 0002. Leave out private and generated directories

- **Date:** 2026-10-11
- **Status:** accepted

## Context and problem statement

The private build repository holds directories that do not belong in a public
repository. Some name private source files. Some record a finished build. One
is generated.

## Considered options

- Import every directory.
- Import every directory and edit the private parts.
- Leave out `docs/inputs/`, `docs/plan/`, `docs/evidence/`, `.beads/` and
  `dist/`.

## Decision

Chose to leave the five directories out.

## Rationale

`docs/inputs/`, `docs/plan/`, `docs/evidence/` and `.beads/` name private
source files or record a build that is finished. The rulebook in
`docs/inputs/` is already public on the shop site. `dist/` is generated by the
client build. Editing these files costs more than their value to a reader here.

## Consequences

- The import has fewer files to check for private content.
- A link from an imported file into one of these directories must be repaired
  or removed.
- A command that rebuilds artwork from the private source files does not run
  from this repository alone.
